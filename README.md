# 文献精读助手

导入英文文献 PDF，**每段英文下方直接显示中文译文**，右侧栏给专业名词和定义，选中任意词就地解释。给需要精读文献的人用。

Windows 和 macOS 都能跑（同一份代码，界面借用系统自带的 Chrome / Edge 开一个无地址栏窗口）。

不接 WPS、不联网同步、不上传任何东西。数据全部在你自己电脑上。

---

## 三步用起来

**1. 选数据目录**

第一次打开会让你选一个文件夹，用来放术语库、译文缓存和配置。

建议放在本地磁盘（比如 Windows 的 `D:\文献工具数据`，Mac 的 `/Users/你的用户名/Documents/文献工具数据`）。**不要放 OneDrive、坚果云、iCloud 这类同步盘** —— 同步客户端会在数据库写入途中替换文件，轻则丢数据，重则整个库损坏，而且往往几天后才发现。

**2. 填一个 AI 接口**

界面上先选服务商，**接口地址和模型名会自动填好**，你只需要粘密钥。已内置：阿里云百炼（通义千问）、DeepSeek 官方、月之暗面 Kimi、智谱 GLM，以及「其他 / 中转站」手动填。

各家的地址都由程序按 OpenAI 兼容协议拼接（地址以 `/v1` 结尾就直接用，否则自动补 `/v1/chat/completions`）。

| 服务商 | 接口地址 | 常用模型 |
|---|---|---|
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`（均衡）/ `qwen-turbo`（便宜快）/ `qwen-max`（更强）/ `qwen-long`（长文） |
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| 月之暗面 | `https://api.moonshot.cn/v1` | `kimi-k2-turbo-preview` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |

**百炼的密钥怎么拿**：`bailian.console.aliyun.com` → 实名认证 → 首次登录同意开通（开通免费）→ 右上角「API-KEY 管理」→ 创建 → **完整密钥只显示一次，当场复制保存**。密钥按地域发放，程序默认走华北2（北京），免费额度也只在该地域。

一篇 20 页文献：DeepSeek 约 **3 分钱**；百炼 `qwen-plus` 约 **2~3 毛钱**（输入 2 元/百万 tokens、输出 8 元/百万量级，以控制台为准）。

填完点「测试连接」，看到 ✓ 就说明通了。最多可以存 5 套配置，随时切换。

> 密钥只存在你自己的电脑上（数据目录的 `settings.json` 里），不会打包进程序，也不会传给别人。

**3. 拖入 PDF**

选一篇英文文献，程序会：

- 先抽出段落，界面立刻显示英文原文
- 后台开始翻译，**先出摘要和引言**（十秒左右就能开始读），方法和结果陆续补齐
- 论文里的插图跟着它所在那一页的文字出现，点开放大；没有插图的页也能「看原页」
- **表格按原样截图显示，不翻译** —— 表格里的字是数字和缩写密排，翻成中文会把列宽对齐全毁掉
- **表下的注解跟表走**（缩写是什么、星号代表哪个显著性水平），贴在表格卡片里并翻译
- 首页的作者、单位、投稿日期、DOI 不进正文（那些是排版噪音，翻了只会占地方）
- 翻完自动把专业名词收进术语库，并生成一张文献卡片

看过一遍的文献会缓存，**再打开不花钱**。

## 界面怎么用

| 操作 | 效果 |
|---|---|
| 选中英文单词 | 弹出解释，讲的是它**在这句话里**的意思，不是词典释义 |
| 点右侧术语 | 跳到这个词在正文里第一次出现的位置 |
| 「只看中文」 | 临时关掉英文，快速扫大意或复习 |
| A− / A+ | 调字号 |
| 每页末尾的分页条 | 一条横贯的浅色分隔带，写明「第 N 页 / 共 M 页」，旁边常驻「看原页」按钮 —— 长文滚动时一眼能定位读到哪一页、哪里换了页 |
| 点插图 / 页尾的「看原页」 | 放大看这一页的原图 |
| 工具栏「原页」 | 按原始版面看**当前读到的那一页**，可滚轮放大、拖动、← → 前后翻页（Esc 关闭） |
| 插图卡片 | 图按原样截图显示，点一下可放大；**图注（Fig. 1 …）贴在图的正下方一起显示并翻译** —— 被版面拆成两截的图注也会接回去 |
| 表格卡片 | 表格按原样截图显示，点一下可放大；**表下的注解（缩写定义、显著性说明）跟在表下面一起显示，并翻译** |
| 「重新翻译」 | 用当前配置把这篇重翻一遍（换过模型、或对上次结果不满意时用）。会重新计费，点之前会问一句 |
| 术语库页 | 搜英文、中文或定义；导出 CSV、导入别人的库合并 |
| 首页文献右侧的 × | 删掉这篇的本机记录（译文/插图/表格缓存 + 文献卡片），原 PDF 不动。删前会问：**只删文献（术语留着）** 还是 **连它带进术语库的词一起删** |

**删文献时那句「共用的词已保留」是什么意思？** 术语库是跨文献积累的：同一个词可能被几篇文献同时带进来。删一篇时，只有这篇用过的词会真的删掉；几篇都靠着的译法只把这篇从「来源」里摘掉，词条留着。所以删掉一篇水刊，不会连带弄坏你读了半年的术语库。为了做到这一点，术语表里除了文件名还记了论文指纹（`source_fps` 列），老库启动时自动补列。

**译文为什么比英文小一号、颜色浅一些？** 故意的。英文是主体，中文是扶手。两者一样显眼时，眼睛会自动滑到中文上，一篇读下来英文一句没进脑子。

## 常见问题

**杀毒软件报毒？**

PyInstaller 打包的 exe 被误报是常见现象，尤其国内安全软件。加信任即可。程序不联网、不读你其他文件，代码在旁边摆着。

**双击后窗口一闪就没，或者完全没反应？**

单文件 exe 启动时要先把内部文件解压到系统临时目录。如果所在文件夹被安全软件或开发工具的沙箱监管（IDE 的项目目录就是典型），解压会被拒，程序会**一声不响地退出** —— 没有窗口、没有提示、连日志都不生成，看起来像"根本打不开"。

搬到 `D:\文献精读助手\` 或桌面新建的文件夹里就能跑。别放 `C:\Program Files`（那里没写权限）。判断方法：看 `startup.log` 在不在，没有就说明程序根本没进到自己的代码。

**点「选择文件夹」没反应，或者选完了没变化？**

先看输入框下面那一行虚线框 —— **可以手动把路径粘进去**，粘完点「用这个位置」或按回车，效果跟选文件夹一样。系统对话框在某些电脑上会被安全软件拦、或被前台窗口压住，这条是留给你绕过去的路。

**窗口打开是一片白？**

浏览器偶尔会给一个空白窗口（页面没加载成功）。程序会自己发现并重开一次，日志里能看到「界面没加载出来，重开一次」。如果反复出现，把 `startup.log` 留着。

**装在中文文件夹里能用吗？**

能。程序的配置目录会自动避开中文路径（Chromium 在中文 `--user-data-dir` 下会白屏），你放在 `D:\文献工具\` 这种目录完全没问题。

**程序文件夹里多出一个 `debug.log`？**

那不是本程序的日志。搜狗输入法这类组件会往「当前工作目录」写自己的调试文件，而你双击 exe 时当前目录就是程序所在文件夹。程序启动时会把工作目录切到系统临时目录，所以正常版本不会再出现这种文件，删掉即可。

**翻译到一半停了 / 报错？**

- 401 → 密钥错了，重新复制一遍，注意别带空格
- 404 → 接口地址不对，检查末尾有没有多余的 `/v1`
- 余额不足 → 去平台充值
- 超时 → 网络问题，重试即可；已经翻好的段落不会重复花钱

**某一段看起来没翻？**

如果那段标着「版面识别不确定」，说明 PDF 里它的段落边界没切准。**故意不翻** —— 给一个错位的译文，比不给更危险，你会把上一段的意思当成这一段记住。这种情况可以对照英文原文自己看。

**双栏论文顺序乱了？**

在「常见问题」里这属于已知限制。绝大多数标准排版的期刊（LaTeX / InDesign 出的）没问题，个别奇怪排版的会有偏差。

**换电脑了怎么办？**

把整个数据文件夹拷到新电脑，第一次启动时选它就行。术语库和缓存都跟着走。术语库也可以单独导出 CSV 备份。

### 踩过的坑（改代码前先看，别重复踩）

**1. pywebview 的 `js_api` 对象不能暴露状态属性**

pywebview 生成 JS 代理时会用 `dir()` 递归遍历 `js_api` 实例的所有属性（跳过下划线开头的）。如果上面挂了窗口对象、数据库连接这类复杂对象，它会一路递归进 .NET 的 `System.Drawing.Rectangle`，在比较时抛 `No method matches given arguments for Rectangle.op_Equality`，**直接卡死 UI 线程，窗口标题变成「未响应」**。

解法在 `app/api.py` 的 `Api.__dir__`：只返回公开方法名，不暴露任何属性。改动 Api 时不要绕过它。

**2. `pywebview` 锁在 5.x**

6.2.1 在 Windows 上同样会触发上述递归问题，且 `maximized=True` 会加剧。5.4 实测稳定。

**3. 「先抽术语、抽完再翻」会把使用者赶走**

v1.0 的顺序是先全文抽术语表，抽完才开始翻第一段。这个顺序看起来讲究（术语先行、译法统一），实际是灾难：抽术语要把全文喂给模型，遇上默认开「思考」的新模型，**实测 9 分钟**才开始翻第一段，整个过程界面上一句中文都没有 —— 使用者只会判断「这软件坏了」，然后关窗。

现在（`translator.py` 的 `translate_document`）是：摘要/引言立刻用空术语表开翻，术语表在**后台线程**里同时抽，抽好了再用于正文。同一篇文献：首批中文从 9 分钟缩到 10 秒，整篇从 18 分半缩到 57 秒。

**4. 「思考」对翻译只是纯损耗**

qwen3.8-flash 翻同一段话：开思考 7.1 秒 / 417 输出 token；关思考 1.3 秒 / 45 token。译文质量看不出差别，成本差 9 倍。`llm.py` 对百炼的 qwen3 系列自动带 `enable_thinking: false`；被服务端拒绝（有些中转站会 400）就自动去掉该参数重发，不让使用者为这件事改配置。

**5. 插图：整页渲染不够，要按区域裁**

论文的图常常只占半页。整页截图缩到正文宽度，坐标轴刻度和分组标签全糊掉，等于没有。
`pdf_reader.page_figures()` 用 `page.get_image_info()` 拿位图块的 bbox（小于 90pt 的是 logo/二维码，丢掉；重叠八成以上的合并），`render_page()` 按 bbox 裁出来渲染。
纯矢量画的流程图 `get_image_info()` 看不到，那类页由前端的「看原页」兜底 —— 宁可多给一个入口，也不瞎猜区域把正文裁进图里。

**5b. 图注要贴着图，而不是飘在正文里**

图注（`Fig. 1 …`）是**文字层**，被解析成 `caption` 段落混在正文里按阅读顺序显示；插图是**位图区域**，统一在页末渲染。两套东西没有关联，于是图注出现在正文中间、中间还隔着好几段正文，图却在页尾 —— 对不上号。表格的注解早就贴进了表格卡片，图这边漏了。

改在渲染层配对（`app.js` 的 `planFigureNotes`），不动后端解析、不用改缓存版本：**按页**把「以 `Fig/Figure/图 + 编号` 开头且后端判为 `caption`」的段落摘出来，按插图 bbox 上沿 y 排序后一一对应，贴到图的正下方。为什么在前端做：配对只用 `page` / `kind` / `text` / `figures bbox`，这些缓存里本来就有，老文献重新打开就能享受，不必重新解析或重翻。

几个通用规则（拿 Springer、Cell 两篇实测过，不是照某一篇调的）：
- **被版面拆成两截的图注会接回去**：主注之后无编号的小写 `caption`（`#46 Fig.1…` + `#50 show the individual data points…`）跟着主注一起走。所以 `body` 正文不能当断点 —— 两截之间常常夹着好几段正文。
- **表格标题、章节标题是断点**：`Table 1 …` 和 `heading` 会切断归位，免得表下的 `* p<0.05` 被黏到上一张图。
- **注比图多 / 该页没有位图（矢量图）就留在正文**：不硬塞、不丢内容。
- 图注仍走原有翻译与回填，`zh` 容器用 `data-note-id` 标记，`zhEl(id)` 照常命中。

**6. 首页的作者单位是「双栏小字」，而首页会被判成单栏**

大标题和摘要横跨整页，`detect_layout` 因此把首页判成单栏，于是底部那块**两栏**的作者单位按单栏处理 —— 左右两栏同一水平线上的行被 `join_lines` 拼成一句，出来是
`University Hospital Düsseldorf, Heinrich Heine University p.pieperhoff@fz-juelich.de`
这种把两个不同单位缝在一起的东西。

`_strip_front_matter()` 把首页三块直接扔掉：标题以上（期刊名、DOI、ORIGINAL PAPER）、标题到摘要之间（作者、单位、投稿日期）、页底小字（通讯方式、版权、基金）。判据是「首页 + 页面下半部 + 字号小于正文 + 命中机构/邮箱/版权特征」，三个条件都满足才动手，避免误伤正文。

**7. 表格是跨栏元素，会连带把整页判成「版面不确定」**

`split_page_regions` 把跨中线的行当通栏元素。表格恰恰横跨两栏，而且落在页面中部 ——
于是 `max_y >= 页高 * 0.45`，整页 `uncertain`，十几段正文全部 `layout_uncertain`。
v1.1 之前 `trusted` 直接看 `flags`，结果是**一页有个表格，整页不翻**，界面上写「无法识别，宁愿不翻」。

现在两头都改：`page_tables()` 把表格区域连文字一起从正文剔除，单独存成 `kind="table"` 的占位段落；同时 `trusted` 只看 `kind`，版面顺序不确定**不再是拒绝翻译的理由** —— 顺序偏一点远好过整页英文。

**7.1 表格检测不要用 PyMuPDF 的 `find_tables`**

它是现成的，但新版走 onnx 模型：这篇 13 页的文献实测**光检测就要 18.6 秒**（每页 1~2 秒），
「打开文献」会从半秒变成二十秒；而且依赖 onnxruntime + numpy，打包进 exe 还要多几十兆。

自己按坐标判（`page_tables`）：表格的每行都会被切成 3 个以上间隔明显的格子，正文的行不会。
判据是「一行 ≥3 格 + 格子内容多半短（数字、缩写、值）+ 连续 ≥3 行」，
再向外把「整行合并」的那种行（只写一个 `PCL-R`）吞回来。
13 页检测 **0.07 秒**，零依赖。宁可漏（漏了只是表格文字留在正文里，内容不丢），也不要误判 ——
误判会把正文裁进「表格」图里，读者看到的直接是缺页。回归测试见 `dev/test_table.py`。

**8. Springer/Wiley 的软连字符**

行末断词抽出来是 `con\xadsistently`（U+00AD），看着像乱码，模型还会当两个词。
`join_lines()` 里专门处理：行尾是软连字符就把两截直接接上（`consistently`），行尾是普通 `-` 才按传统断词规则还原。

### 段落切分的判据（改 `pdf_reader.py` 前必读）

- **双栏判断按「行的跨度」分左右，不按中心**：`x1 <= 中线` 才算左栏、`x0 >= 中线` 才算右栏，横跨中线的行两边都不算。按中心分的话，通栏的标题/摘要会被算成「左栏」，中文单栏的整行也是，凑够数就误判成双栏，整页顺序全乱。
- **跨中线占比的门槛要放宽到 0.5**：单栏页几乎所有行都压在中线上（0.8 以上），双栏页几乎不跨（0.1 以下），中间那一档全是「首页上半通栏、下半双栏」。卡在 0.15 时首页一律判成单栏，左右两栏同一水平线的行被缝成一句，一篇 15 页的文献能缝出一万字的单段。
- **头部区到哪儿为止，看「右栏第一行在哪个 y」**，不要写死「页高 45%」。首页的摘要常写到 50%~60%，写死就判不过，整页被按中线劈开。
- **切段的三个信号**：行间距 > 0.55 倍行高、字号差 > 0.8、首行缩进 > `max(2, 0.55×字号)`。缩进门槛一定要和字号挂钩：很多期刊缩进只有 8pt（正文 9.8pt 的 0.8 倍），卡 1.1 倍字号会把整栏并成一段。
- **粗细也是切段信号**：`Introduction`/`Methods` 常和正文同号，只靠加粗区分。整行 60% 以上字符是粗体才算「粗体行」，夹个把粗体缩写不算。
- **跨栏/跨页段落合并**：主判据是**首行是否顶格**（学术排版段落首行缩进、续行顶格），不是结尾有没有句号 —— 段落内部在句号处跨页是常态。合并时要跨过插进来的表格/表注占位（一段话常在表格上方起头、表格下面接着写）。
- **空行分段（不缩进）的版式**退回启发式：句子已收尾 + 下一段大写/数字开头 = 两段，**不合并**；没在句末断开（行排满或连字符）= 续行，合并。顺序不能反 —— 先看「行排满没排满」会把两端对齐的正文焊成巨段。
- **合并后的段落放哪一页**：放**字数多的那一页**。它是从那一页正文里被挖走一半的，放回去才不突兀；按起始页放会让下一页开头凭空少一块。归属页变了之后要按页稳定排序（`raw_paras.sort(key=page)`），否则前端先出现第 4 页又缩回第 3 页。
- **合并的边界**：字号差超过 1pt 不合并（正文 10pt / 图注 8.5pt 是两种东西），下一段以 `Fig.`/`Table` 开头不合并（那是另一张图的说明）—— 否则正文末尾会接出「…p-value (uncorr.) Fig. 3 Associations of…」。另有 `MAX_MERGED_CHARS = 3200` 硬上限，判断错时至少不会产出一段看不清的巨块。
- **短标题不能按长度过滤**：`Abstract`、`2. Methods` 只有 8~10 个字符，加长度门槛会把章节标题全丢掉。

### 已经用不同出版社的文献验过（别只盯着一篇调阈值）

同一套规则跑过 Oxford（Briefings in Bioinformatics，7.8pt 小字密排、无缩进空行分段）、Springer（双栏 + 通栏摘要）、J Cheminformatics（8pt 缩进、标题只加粗不加号）：

| | 修前 | 修后 |
|---|---|---|
| Briefings in Bioinformatics | 一段文字全是 `Theabilityofacompoundto…`（dict 层没空格） | 用 words 层补回空格，摘要可读、可译 |
| J Cheminformatics | 222 段，最长 10179 字（首页按单栏排序，左右栏缝在一起） | 99 段，最长 2548 字 |
| Springer（原文献） | 72 段 | 76 段（多出来的是被加粗切开的 `Supplementary` 等小标题） |

**粘连文字的修法**：一行又长又没有任何空白时，拿 `page.get_text("words")` 里落在同一 y 区间的词重拼一遍（`_rebuild_from_words`）。空格是画上去的间距、不是空格字符，这是 Oxford 系 PDF 的常见写法。
